## 怎么维护（规则）

| 时机 | 动作 |
|---|---|
| 立项 / 讨论定案 | 进「📋 待办」；有设计细节的**只放一行 + 链接**到 ai-roadmap.md 或 solutions/，不复制 |
| 事情做完 | 从「进行中/待办」挪到「✅ 已完成」（保留最近 10 条，更早的删） |
| 决定押后 | 进「⏸️ 押后」并**必须填触发条件**（何时重新评估）——这是防遗忘的核心 |
| 发现新 follow-up | 随手加进「待办」或「押后」 |

> 分工：看板 = 执行视图（做什么、到哪步）；`ai-roadmap.md` = AI 设计文档（为什么、怎么做）；`solutions/` = 踩坑根因。两边不重复。

### 对话查账：模型意图可能覆盖问法里的显式数字
真实 Key 验证观察（2026-10-09）：问「近三个月支出趋势」，规则解析出 trend_months=3，但模型意图未带该字段（缺省 6）并整体替换规则结果 → 答了六个月序列。数据正确、只是范围不符问法。
- [ ] 改法：规则已解析出显式数字参数（trend_months/top_n/days/months）时优先采用，模型只补规则没答出的部分；或在意图提示词里带上规则预解析结果作提示。触发即做：用户反馈范围不符 / 下次动 ai-ask 意图合并逻辑时顺手

### 叙述核验同族残余（低危，零值豁免的边界，PR #5 审查确认）
- trend 零月可被「蒸发」：序列含 0 的月份不进关键金额，回答只列非零月也过核验（模板会列全）——完整性欠缺，无 compare 那种关系性误导
- budget used=0 时已用与剩余同值合并，一句「预算 ¥100」即过、可不提已用/剩余
- [ ] 触发即做：用户反馈统计口径不完整时，再评估是否给 trend/budget 加月份数/三项强制
