# 版本登记与管理（docs/versions.md）

> 版本号规则、三件套同步义务、发版流程与**逐版登记台账**。规则短句在 `AGENTS.md`（「版本三件套」「标签=发版」），
> 协作流程全文在 [collaboration.md](collaboration.md) §2，本文档负责**展开 + 登记**；发版执行状态（谁还没推 tag）看 [BOARD.md](BOARD.md)「发版收尾」。

## 1. 版本号规则

- 格式 `vX.Y.Z`（semver 语义按批次落地）：
  - **次版本 X.Y**：一个功能批次一次（如 v1.8.0 = P1 习惯记忆 + P4 后悔药，v1.9.0 = P2 对话查账），或一组较大的 UI/UX 改版
  - **补丁 Z**：bug 修复、小改进、文案与测试补课
- 版本随**批次**走，不随单次提交走：批次内的多个 PR 共享同一个版本号（PR 合并 ≠ 发版，**打 tag 才是发版**）
- `about.js` CHANGELOG 首条的 `tag: '当前版本'` 表示尚未发布（tag 未打）；发版后改为 `''` 并由新首条接管

## 2. 版本三件套（防漂移义务）

发版前**三处版本号必须一致**，缺一不可：

| 处 | 内容 |
|---|---|
| `package.json` | `"version": "X.Y.Z"` |
| `src/lib/about.js` | `CHANGELOG` 首条 `version` + `date` + 条目（应用内「关于」页展示） |
| `README.md` | 「📦 更新记录」首节 `### vX.Y.Z（日期）` |

- 条目口径：about.js 面向用户（做了什么、怎么用）；README 首节同一批内容的精简版
- 防漂移：看板已登记「selfcheck-static 版本三件套一致性断言」待办（三处版本号不一致即跑批变红）；落地前靠人工核对
- 历史缺口：about.js CHANGELOG 自 v1.3.0 起逐版齐全，v1.1.x / v1.2.0 / v1.2.1 无条目（以 §4 登记表为准），不回补

## 3. 发版流程（谁做什么）

```
批次完成（全量套件绿 + PR 合并 + 版本三件套更新）
  → 维护者确认发版
  → 维护者打/推 tag：git tag vX.Y.Z && git push origin vX.Y.Z（SSH）      ← AI 永不自动执行
  → CI 按 tag 构建双架构镜像（amd64/arm64）发布 GHCR，镜像 tag = 版本号 + latest
  → GHCR 包可见性（首次需手动设 Public）
  → NAS 切镜像：docker compose pull && up -d（ghcr.milu.moe 中转）
  → 在本文件 §4 与 BOARD「发版收尾」登记结果
```

- tag 触发的 CI/GHCR/NAS 均为对外动作，**逐项等维护者确认**（collaboration.md §2）
- 已合并但未打 tag 的版本 = 「待发版」状态，登记表标 ⏳

## 5. 常用核对命令

```bash
git tag -l | sort -V            # 已发版本（tag 列表）
git log --oneline -1 v1.7.7     # 某版本对应的提交
grep '"version"' package.json   # 三件套之一（另两处见 §2）
```
